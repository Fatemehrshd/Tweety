# Twitter-like Social Network — MVP

Production-ready MVP of a Twitter-like social network: register/login, profiles (bio + avatar),
text posts (280 chars), and a global Explore feed — plus an MCP server so an AI agent can drive the same API.

**Stack:** Next.js (frontend + backend) · TypeScript · PostgreSQL + TypeORM · Redis (ioredis) · Swagger/OpenAPI (`@asteasolutions/zod-to-openapi`) · pnpm workspaces

| Piece    | URL (local dev)              | How to run longest |
|----------|------------------------------|--------------------|
| Frontend | http://localhost:3000        | `pnpm dev:frontend` |
| Backend  | http://localhost:4000        | `pnpm dev:backend` |
| API docs | http://localhost:4000/api/docs | served by backend |
| Health   | http://localhost:4000/health | DB + Redis checks |

> New here? Read this file top-to-bottom, then open [`docs/PROJECT_REPORT.md`](docs/PROJECT_REPORT.md)
> for the why-behind-every-decision (with alternatives considered).

## 1. What you get

- **Auth:** register, login, logout, silent refresh with rotation. Short-lived JWT access token (~15 min) + long-lived refresh token (30 d) in an `httpOnly` cookie — never in `localStorage`.
- **Profiles:** public profile by username, own profile (`GET/PATCH /api/users/me`), bio (≤160), avatar upload (JPEG/PNG/WebP/GIF, ≤5 MB) or avatar URL, password change (current password required).
- **Posts:** create / view / edit / delete *own* posts; 1–280 chars; author + `createdAt`/`updatedAt` on every post.
- **Explore:** global newest-first feed, cursor-paginated.
- **MCP server (`mcp/`):** 13 tools over stdio (Claude Desktop) or Streamable HTTP — a thin interface over the backend API, no duplicated logic.

**Known gap (not yet built):** there is **no persistent Audit Log and no Admin Panel/role** in this codebase. The original feature request for those has not been implemented. See `docs/PROJECT_REPORT.md` §10 for the proposed design if you pick it up.

**Rule to internalize:** backend code is organized *by feature* (`modules/<feature>/`), each with
route → service → repository. Services never touch the ORM directly; cross-module calls go through the
other module's service (`users` calls `posts`' `getPostsByAuthor`, never its repository). Shared code
lives in `modules/shared/` and must stay feature-free.

## 7. How the pieces fit (60-second tour)

**Request path (backend):** `middleware.ts` (CORS + `X-Request-ID` gen/propagation) → route handler
(`app/api/.../route.ts`: `withErrorHandling(withRequest(...))`, Zod `parseJsonBody/parseQuery/parseParams`)
→ service (`modules/<f>/ *.service.ts`, business logic + ownership checks) → repository
(`*.repository.ts`, the only files that import the TypeORM DataSource) → Postgres.
`requireAuth()` reads identity from `AsyncLocalStorage`; `requireAuth` throws `AuthError` (401) when absent,
services throw `ForbiddenError` (403) for чужое (another user's) resources. Every error is a typed `AppError`
subclass rendered by the central `error-handler` as `{ code, message, details?, requestId }`.

**Auth flow:** `POST /api/auth/register|login` → `{ accessToken, user }` + `Set-Cookie: refresh_token=…; HttpOnly; SameSite=Lax; Path=/api/auth`.
The frontend keeps the access token in memory (`AuthContext`), sends `Authorization: Bearer …`, and includes
cookies so `/api/auth/refresh` (cookie-scoped path) can rotate: old refresh token deleted, new one issued
(`rotateRefreshToken` pipeline). Refresh revocation lives in Redis with 30-day TTL. Logout deletes the Redis
entry and clears the cookie — even with no cookie it still returns 204.

**Frontend:** `AuthContext` (`login/register/logout/refreshAuth`, refresh-on-mount) → pages are `"use client"`,
all HTTP goes through `lib/api-client.ts` (`api.*` + `ApiError`), every network call renders loading/error/empty
states. Avatars: file validation happens client-side *and* server-side; upload is `multipart/form-data`
(`FormData`, no manual `Content-Type`), display uses the absolute URL the backend returns.

**MCP:** `server.ts` registers 13 Zod-validated tools; `api.ts` is the only HTTP layer (10 s timeout, one retry
on network failure only, never on 4xx); `session.ts` keeps one in-memory session per client (stdio = one client,
HTTP = one per MCP session id) with exactly one silent refresh on 401. Avatar upload is deliberately absent
(binary over stdio); use `users_update_me` with a URL instead. See `mcp/README.md` for the tool table.

## 8. API quick reference

Swagger UI: http://localhost:4000/api/docs · raw JSON: `GET /api/docs` (generated from code via
`zod-to-openapi`, never hand-maintained).

| Method & path | Auth | Notes |
|---------------|------|-------|
| `POST /api/auth/register` | — | `{email, username, password}` → 201 `{accessToken, user}` + cookie |
| `POST /api/auth/login` | — | `{email, password}` → 200 + rotated cookie |
| `POST /api/auth/refresh` | cookie | rotates refresh token |
| `POST /api/auth/logout` | cookie (optional) | 204 always |
| `GET /api/users/me` | Bearer | own profile |
| `PATCH /api/users/me` | Bearer | `{bio?, profilePictureUrl?}` |
| `PATCH /api/users/me/password` | Bearer | `{currentPassword, newPassword}` |
| `POST /api/users/me/profile-picture` | Bearer | `multipart/form-data file=` |
| `GET /api/users/{username}` | — | public profile |
| `GET /api/users/{username}/posts?cursor&limit` | — | cursor-paginated |
| `GET /api/posts?cursor&limit` | Bearer | own posts |
| `POST /api/posts` | Bearer | `{text 1–280}` → 201 |
| `GET /api/posts/{id}` | — | single post |
| `PATCH /api/posts/{id}` | Bearer | owner only, else 403 |
| `DELETE /api/posts/{id}` | Bearer | owner only → 204 |
| `GET /api/explore?cursor&limit` | — | global feed |
| `GET /health` | — | `{status, checks:{db, redis}}`, 503 when degraded |

Error shape everywhere: `{ "code": "VALIDATION_ERROR|AUTH_ERROR|FORBIDDEN|NOT_FOUND|CONFLICT|INTERNAL_ERROR", "message": "…", "requestId": "…" }`.
List endpoints take `cursor` + `limit` (1–100, default 20) and return `{ items, nextCursor }`.

## 9. Working rules (from AGENTS.md — don't skip)

- **Branching:** `main` ← only from `develop`; features branch off `develop` as `type/short-desc`, one change per branch, rebase before PR, delete after merge. Conventional Commits; `fix→patch, feat→minor, BREAKING CHANGE→major`; tag `vX.Y.Z` on `develop→main`.
- **Before a PR:** typecheck every side you touched. After a feature: add/extend tests for its core logic.
- **Backend:** validate every input with Zod before business logic; typed errors only; structured logs with trace ID (pino, secrets redacted); paginate every list; no N+1 (joins/batched loads); stateless services; heavy work → job queue, not inline; external calls get timeout + bounded retry; multi-step writes in a transaction; keep Swagger in sync in the same change.
- **Frontend:** Server Components by default, `"use client"` only for interactivity; client validation mirrors (never replaces) backend; centralized `api-client` only; handle loading/error/empty; mutations never auto-retry.
- **MCP:** thin HTTP calls only — no DB/auth/business logic, no imports from backend/frontend; keep `mcp/README.md` tool table in sync; localhost bind + 4 MB cap on HTTP.

## 10. Troubleshooting

| Symptom | Fix |
|---------|-----|
| `Cannot reach backend` / empty feed | backend not running or wrong `NEXT_PUBLIC_API_BASE_URL` / `API_BASE_URL` |
| 401 right after login | clock skew (15-min JWT) or missing `Authorization` header; refresh once, then re-login |
| `refresh_token` cookie missing | frontend must use `credentials: "include"` (already in `api-client`); cookie `Path=/api/auth` is only sent to auth routes by design |
| Migration fails / `relation already exists` | DB drifted — never hand-edit `migrations/`; generate via TypeORM and run `pnpm db:migrate` |
| Avatars 404 on frontend | `PUBLIC_BASE_URL` wrong, or `backend/public/uploads/` wiped (local-disk store, see report §4) |
| `/health` → 503 `degraded` | read `checks`: `db` down = Postgres/creds; `redis` down = Redis/`REDIS_URL` |
| `Cannot access 'User' before initialization` | circular entity import + `emitDecoratorMetadata` — it is **off** on purpose; keep relation targets as function-form (`() => User`) with explicit column types |
